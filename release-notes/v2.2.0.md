# OverkizClient 2.2.0

This minor release adds a supported cloud realm and authentication protocol while preserving existing signatures, enum numbers and target frameworks. No new runtime dependencies are added. The redundant .NET Framework `System.Net.Http` 4.3.4 NuGet dependency is replaced by the framework reference, avoiding an older reference-assembly conflict in independent consumers; the library DLL bytes remain unchanged by that packaging correction.

## Smart Control authentication

Select `Server.SauterSmartControl` for Sauter Smart Control appliances. `Server.SauterCozytouch` remains the separate Cozytouch JWT integration for heating devices. Brandt Smart Control now follows the same current middleware flow with its own partner value:

1. POST a typed email/password/partner model to the Smart Control session service.
2. Carry its session cookie into the typed profile/JWT exchange.
3. Submit only the JWT to the Overkiz login endpoint, then optionally register the event listener.

The library's default HttpClient supports cookies. An application-supplied HttpClient must also support cookies and be dedicated to this client. The application retains ownership of a supplied client. Middleware cookies remain scoped to their origin; bearer tokens are not sent to middleware. No password, JWT, cookie or response body is included in the new authentication error messages.

`BrandtBadCredentialsException` identifies a rejected middleware login; `BrandtServiceException` identifies service/JWT failures for either Brandt or Sauter. Existing generic Overkiz cloud error mapping remains in use for the final cloud login. No authentication operation automatically replays a device command.

## Additional upstream names

`EventName.OgcpTokensRefreshCompleted`, `UIWidget.DynamicAudioPlayer` and `UIWidget.DynamicElectricalSensor` are appended without renumbering existing enum members. Both upstream audio-player spellings are recognized by the existing case-insensitive widget accessor. Event objects retain the exact wire name, including `OGCPTokensRefreshCompletedEvent`.

States and attributes already retain their string names and typed values. Regression coverage includes all 35 added upstream state/attribute names in the audited window, including oven metadata, energy production, luminance, battery level and commissioning events. Unknown future names continue to round-trip.

## Safe overlapping calls

Independent reads can overlap. Authentication and token rotation, listener operations, gateway selection, cached setup replacement and commands are sequenced. Overlapping refresh calls use the first completed rotation; headers belong to individual requests. Disposal cancels and drains admitted calls, rejects subsequent calls and prevents late responses from republishing cleared session state. A supplied HttpClient remains application-owned and must be dedicated to this client. Returned mutable models require caller coordination.
