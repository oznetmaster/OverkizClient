# OverkizClient v1.1.5

This patch fixes response-handling bugs found while adding a standalone NUnit suite. The library continues to target .NET Framework 4.7.2 and .NET 10, with no public API or production dependency changes.

## Fixes

- Standard and CozyTouch login now recognize successful JSON responses correctly; CozyTouch also sends its Basic authorization header with the OAuth token request.
- Typed state accessors handle JSON numeric and boolean values, and JSON serialization no longer invokes incompatible typed convenience properties.
- Events correctly populate `DeviceUrl` from `deviceURL`.
- Unknown enum names use the declared `Unknown` member even when its numeric value is not zero.
- Missing listener, execution and local-token response IDs produce `OverkizException` instead of dictionary-key exceptions.

## Automated tests

The solution now includes 154 offline NUnit cases for each target framework. They cover authentication, API request/response handling, setup and devices, commands and scenarios, events, Rexel gateway selection, local-token management, error mapping and client lifetime. Tests use a scripted HTTP handler and require no credentials, devices or network access.

Local validation passed all 154 cases in both Debug and Release on both frameworks. Two consecutive runs in one .NET Framework process also passed. The release workflow runs both framework targets before publishing. These tests do not establish live vendor-service compatibility; Nexity Cognito authentication remains unimplemented.

## Install or update

```powershell
dotnet add package OverkizClient --version 1.1.5
```

NUnit and the test adapter are not dependencies of the published library package. Existing consumers can update without changing their public API usage.

See the [test guide](https://github.com/oznetmaster/OverkizClient/blob/v1.1.5/OverKizApi.Tests/README.md), [changelog](https://github.com/oznetmaster/OverkizClient/blob/v1.1.5/CHANGELOG.md) and [full changes](https://github.com/oznetmaster/OverkizClient/compare/v1.1.4...v1.1.5).
